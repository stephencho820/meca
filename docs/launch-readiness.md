# MECA 출시 전 검증 및 개인정보 운영 체크리스트

> 준비 중. 이 문서는 법률 자문을 대체하지 않으며, 실제 고객 사용 전 책임자 확인이 필요합니다.

## 자동화 검증
- GitHub CI: TypeScript, Next.js 빌드, PostgreSQL 예약/CRM/직원 자원/개인정보 요청 SQL 테스트.
- Chromium E2E: 데모 예약 생성 → 개인 예약 링크 → 취소, 관리자 직원·리프트/작업/개인정보 메뉴 검증.
- 실제 정비소 실계정 로그인/데이터를 사용하는 E2E와 모바일 실기기 테스트는 별도로 필요합니다.

## 실정비소 수락 테스트
- [ ] 테스트 정비소 가입·이메일 인증·로그인.
- [ ] 테스트 예약 접수 및 관리자 반영, 예약 수정과 취소.
- [ ] 리프트/정비사 중복 배정 차단, 입고→정비→출고.
- [ ] 고객·차량 재방문 연결, 정비소 두 곳 데이터 분리(RLS).
- [ ] 고객 예약 관리 링크로 개인정보 요청 → 관리자 검토 메뉴 확인.
- [ ] 모바일 Chrome/Safari 검증 및 테스트 정보 정리.

## CAPTCHA 및 IP 방어 (남은 출시 게이트)
- Cloudflare Turnstile 사이트 키와 서버 비밀 키를 발급한 후 MECA Vercel Production 환경변수 NEXT_PUBLIC_TURNSTILE_SITE_KEY 와 TURNSTILE_SECRET_KEY 를 모두 등록하세요. 한쪽만 있으면 예약 요청이 거부됩니다. 두 키가 없으면 보호 기능이 켜지지 않습니다.
- Turnstile API 응답은 서버에서 검증합니다. 키는 GitHub나 채팅에 공유하지 마세요.
- Vercel Dashboard → MECA → Firewall → Configure → New Rule : Request Path=/api/bookings, Method=POST, Rate Limit, IP별 10회/분 등을 검토해 설정하세요. 차단 전에 로그로 정상 이용자 영향을 확인하고 적용 비용을 확인해야 합니다.
- Next.js/WAF를 우회한 직접 Supabase 예약 RPC는 현재 정비소+전화번호별 제한이 있지만, 전화번호 변경을 통한 스팸까지 차단할 수는 없습니다. 운영 출시 전 Supabase 공개 RPC를 전용 보안 백엔드로 이전하는 설계가 필요합니다.

## 개인정보 처리
- 수집 항목과 법적 근거, 처리 목적, 개인정보 책임자와 문의 채널, 보관·파기 기간, 제3자 제공/국외 이전 여부 등을 정비소와 MECA 운영 구조에 맞춰 법률 검토 후 개인정보 처리방침에 게시합니다.
- 고객은 비밀 예약 관리 링크로 열람/정정/삭제 요청을 접수할 수 있으며, 정비소 소유주에게만 요청 목록이 보입니다.
- 처리 절차: 요청 접수 → 추가 본인 확인 → 법정 보관 의무 검토 → 정정/안전한 파기 또는 제한 및 기록 → 요청자 통지 → 담당자 종료 확인.
- 요청 등록 또는 종료만으로 개인정보를 삭제하지 않습니다. 구체적인 법정 보관기간과 증빙 필요성을 확정하기 전에는 자동 삭제 Cron을 만들지 않습니다.
- 백업, 접근통제 감사 로그, 실제 데이터 파기 실행 기능, 유출 대응 절차는 추가 구현이 필요합니다.

## 상태
- SOLAPI/카카오 알림톡: 사용자 요청대로 보류. 실제 발송 비활성화.
- CAPTCHA: 코드 준비, 키 미설정이면 비활성화.
- IP WAF 규칙: 운영자가 비용과 정상 트래픽 확인 후 설정해야 함.
- 개인정보 자동 삭제: 의도적으로 미구현. 법률 검토 후 설계.
